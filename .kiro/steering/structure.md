## Where new files go

- **Client feature** (map, avatars, animations, camera, movement, proximity,
  interaction panel, minimap, HUD, drawer UI): under `client/src/`, in the matching
  subdir (`game/` for the Pixi world and its `layout/` / `scenes/`, `ui/` for React
  panels, `term/` for the terminal view, `net/` for wire access, `state/` for the
  store). Pure helpers get a test in `client/test/`.
- **Server feature** (plugin lifecycle, HTTP, token gate, sources, event relay,
  command/terminal proxy): under `server/`. A new agent backend is a new file in
  `server/sources/` that implements the `AgentSource` surface; terminal behavior
  goes in `server/term/`; shared validation in `server/sources/commands.mjs`. Add a
  `node:test` file under `server/test/`.
- **Plugin action / pane**: a Node entrypoint in `scripts/`, wired up in
  `herdr-plugin.toml`.
- **Tests**: `server/test/` and `client/test/` (both pure helpers), run together by
  `npm test` (`node --test server/test client/test`).

## Ownership seam

One owner per directory; the owner merges freely there, and changes to the other
person's directory go through them.

| Area | Owner | Paths |
| --- | --- | --- |
| Game interface | Frontend | `client/` |
| Harness integration | Backend | `server/`, `scripts/`, `herdr-plugin.toml` |
| Contract | Both | `PROTOCOL.md` |
| Demo | Both | `docs/demo.md` |

- The frontend never talks to herdr directly; the backend never draws pixels.
- `client/` and `server/` meet only at `PROTOCOL.md`: a stream of JSON snapshots
  (SSE) plus the POST command, create, and terminal endpoints.
- Any feature that needs both sides (e.g. "show the agent's live terminal") starts
  as a change to `PROTOCOL.md`, approved by both owners, before either side writes
  code against it.
- The server serves the built client from `client/dist/`; that build output is the
  only runtime coupling between the two directories.
